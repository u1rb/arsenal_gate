=== FILE FORMAT: Cboe PITCH 2.X Multicast Depth of Book Protocol ===
Version: 2.41.62
Byte Order: Little Endian (all multi-byte fields)
Protocol Type: UDP Multicast (real-time), TCP (Gap Request Proxy, Spin Server)
Date: November 18, 2025

--- OVERVIEW ---
Cboe PITCH 2.X is a market data feed protocol for real-time depth of book 
quotations and execution information. Messages are delivered via UDP multicast
with TCP fallback for gap recovery and spin requests.

Key characteristics:
- All binary fields use Little Endian byte ordering
- Messages are variable length, starting with a length byte
- Multiple messages can be bundled in a single UDP frame
- Sequence numbers: 32-bit unsigned, rollover from 4,294,967,295 to 1 (not 0)
- Sequence 0 indicates un-sequenced messages

--- DATA TYPES ---

Type                | Size    | Description
--------------------|---------|--------------------------------------------------
Binary              | varies  | Unsigned integer, Little Endian
Alphanumeric        | varies  | Left-justified ASCII, space-padded right
Printable ASCII     | varies  | Left-justified ASCII (0x20-0x7e), space-padded
Binary Short Price  | 2       | LE u16, 2 implied decimal places (÷100)
Binary Long Price   | 8       | LE u64, 4 implied decimal places (÷10,000)
Bit Field           | 1       | Each bit is a boolean flag (bit 0 = LSB)
Binary Date         | 4       | LE u32, base-10 is YYYYMMDD (e.g., 20231030)
Multiplier          | 4       | LE u32, 1 implied decimal place (÷10)
Time Offset         | 4       | LE u32, nanoseconds since last Time message

--- MAGIC NUMBERS / MESSAGE TYPE CODES ---

Gap Request Proxy Messages:
  0x01 = Login
  0x02 = Login Response
  0x03 = Gap Request
  0x04 = Gap Response

Spin Server Messages:
  0x01 = Login
  0x02 = Login Response
  0x80 = Spin Image Available
  0x81 = Spin Request
  0x82 = Spin Response
  0x83 = Spin Finished
  0x84 = Instrument Definition Request
  0x85 = Instrument Definition Response
  0x86 = Instrument Definition Finished

  0xB1 = Time Reference (C1 Options Only)
  0x20 = Time

  0xBD = Transaction End (Options Only)
  0x21 = Add Order - Long

  0x24 = Order Executed at Price/Size
  0x25 = Reduce Size - Long
  0x26 = Reduce Size - Short
  0x27 = Modify Order - Long
  0x28 = Modify Order - Short
  0x29 = Delete Order
  0x2A = Trade - Long
  0x2B = Trade - Short
  0x30 = Trade - Expanded

  0x2D = End of Session
  0x2E = Symbol Mapping (Options Only)
  0x31 = Trading Status
  0xD2 = Width Update (Options Only)

  0xD1 = Options Auction Update (Options Only)

--- STRUCTURES ---

SequencedUnitHeader (wraps all messages)
  @offset | @size | field_name   | type   | endian | description
  --------|-------|--------------|--------|--------|------------------------------------
  0       | 2     | hdr_length   | u16    | LE     | Total length including header + all messages
  2       | 1     | hdr_count    | u8     | N/A    | Number of messages following header
  4       | 1     | hdr_unit     | u8     | N/A    | Unit ID for messages in this block
  4       | 4     | hdr_sequence | u32    | LE     | Sequence of first message (0=unsequenced)
  Total Length = 8 bytes
  
  Notes:
    - Heartbeat: hdr_count = 0 (no messages follow)
    - Next sequence = hdr_sequence + hdr_count (handles rollover at 4,294,967,295→1)
    - Sequence 0 = un-sequenced message
    - Multiple messages share one header with implied sequential sequence numbers

--- VARIABLE LENGTH RULES ---

Message Length Determination:
- First byte of every message is the length (including the length byte itself)
- Length field allows parsing unknown message types (skip length-1 bytes)

Symbol Field Sizes:
- Standard: 6 bytes (Printable ASCII, space-padded)
- Expanded (ISRA plan): 8 bytes (Printable ASCII, space-padded)

Options vs Equities Message Differences:
- Order Executed: +1 byte for Trade Condition (Options)
- Order Executed at Price/Size: +1 byte for Trade Condition (Options)
- Trade (all variants): +1 byte for Trade Condition (Options)
- Add Order Expanded: +9 bytes for Options fields (Customer Indicator, Client ID, Reserved)
- Trading Status: Different field layouts for Options vs Equities
- Time: +4 bytes for Epoch Time (C1 Options Only)


--- PARSING SEQUENCE ---

1. Parse SequencedUnitHeader (8 bytes):
   - Extract hdr_length, hdr_count, hdr_unit, hdr_sequence
   - If hdr_count = 0: This is a heartbeat message
   
2. For each message (hdr_count times):
   a. Read length byte (1 byte)
   b. Read message_type byte (1 byte)
   c. Based on message_type, parse remaining (length - 2) bytes
   d. Implied sequence = hdr_sequence + message_index
   
3. Sequence Number Handling:
   - Track expected sequence per unit
   - Detect gaps: received_sequence > expected_sequence
   - Handle rollover: 4,294,967,295 -> 1 (skip 0)
   
4. Time Offset Resolution:
   - Maintain last Time message per unit
   - Calculate absolute time: last_time_seconds + time_offset_nanoseconds
   - For C1 Options: Use TimeReference for midnight boundary crossings

5. Book Maintenance:
   - Add Order: Insert into book keyed by Order ID
   - Modify Order: Update price/quantity for Order ID
   - Reduce Size: Decrease quantity for Order ID
   - Delete Order: Remove Order ID from book
   - Order Executed: Decrease quantity; remove if zero
   - Order Executed at Price/Size: Use remaining_quantity; remove if zero
   - Unit Clear: Remove all orders for unit
   - Trade/Trade Break: Informational only (hidden orders)


--- SPECIAL CASES ---

1. Message Type Growth:
   - Cboe may add fields to end of messages without notice
   - Always use length field to skip unknown trailing bytes
   - Parser should handle length > expected gracefully

2. Unknown Message Types:
   - Skip (length - 1) bytes after message_type
   - Do not fail; log warning and continue

3. Framing Differences:
   - UDP: Self-contained; single SequencedUnitHeader per frame
   - TCP (GRP/Spin): May span frame boundaries; use length-based parsing

4. Sequence Rollover:
   - Maximum: 4,294,967,295 (u32::MAX)
   - Rolls to 1 (not 0)
   - Gap requests must handle rollover in ranges

5. Options vs Equities Detection:
   - Based on market/unit configuration (external)
   - Some messages have different lengths
   - Trade Condition byte present only for Options

6. Symbol Mapping (Options):
   - 6-char feed symbols map to 21-char OSI symbols
   - Mapping messages are un-sequenced (sequence = 0)
   - Sent continuously; maintain mapping table

7. C1 Options 24x5 Trading:
   - May cross midnight boundary
   - TimeReference resets at midnight ET
   - Time message Time field resets to seconds from new midnight

8. Reserve Orders:
   - Displayed portion: Order Executed (0x23)
   - Hidden portion: Trade (0x2A/0x2B/0x30) with obfuscated Order ID
   - Refresh: New Add Order with new Order ID

9. Transaction Blocks (Options):
   - TransactionBegin/TransactionEnd bracket related messages
   - Used for symbol state transitions
   - Can be ignored for pure book building

10. Price Interpretation:
    - Binary Short Price: value / 100 (2 decimal places)
    - Binary Long Price: value / 10000 (4 decimal places)
    - Multiplier: value / 10 (1 decimal place)

--- NOM PARSER IMPLEMENTATION NOTES ---

- le_u8, le_u16, le_u32, le_u64 for binary fields

- map_res for converting ASCII to strings

- Use nom::error::VerboseError for debugging
- Implement custom error types for protocol-specific errors
- Handle unknown message types gracefully with alt/fail

Performance considerations:
- Zero-copy parsing where possible using &[u8] slices
- Pre-allocate order book data structures
- Consider SIMD for high-volume scenarios

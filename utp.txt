=== FILE FORMAT: UTP Binary Data Feed Protocol ===
Source Document: UTP Data Feed Services Specification Version 3.0
Version: 3.0 (August 2025)
Byte Order: Big-Endian (Network Byte Order)
Protocol: INET MoldUDP64 (transport layer)

--- DATA TYPES [§1.2, §1.2.1] ---

Type        | Size    | Description                                           | Source
------------|---------|-------------------------------------------------------|--------
byte        | 1       | Single ASCII character (alphanumeric)                 | §1.2.1
short       | 2       | Big-Endian Unsigned 16-Bit Integer                    | §1.2.1
int         | 4       | Big-Endian Unsigned 32-Bit Integer                    | §1.2.1
long        | 8       | Big-Endian Unsigned 64-Bit Integer                    | §1.2.1
byte[]      | N       | Fixed Width ASCII Field (left-justified, space-padded)| §1.2.1
varbyte[]   | var     | Variable Width ASCII Field (length in prior field)    | §1.2.1

--- NUMERIC ENCODING RULES [§1.2.2] ---

- All multi-byte numeric values are Big-Endian (network byte order)
- Prices in `long` fields: 6 implied decimal places (divide by 1,000,000)
- Prices in `short` fields: 2 implied decimal places (divide by 100)
- Volume in `long` fields: 6 implied decimal places (divide by 1,000,000)
- Timestamps (`long`): nanoseconds since Unix Epoch

--- ALPHA ENCODING RULES [§1.2.3] ---

- ASCII encoded
- Left-justified
- Right-padded with space characters (0x20)
- Alphanumeric fields include: byte, byte[], varbyte[]

--- STRUCTURES ---

MessageHeader [§2.1]
    @offset | @size | field_name   | type | endian | description                    | source
    --------|-------|--------------|------|--------|--------------------------------|--------
    0       | 1     | version      | byte | n/a    | Protocol Version (ASCII '1')   | §2.1
    1       | 1     | msgCategory  | byte | n/a    | Message Category               | §2.1
    2       | 1     | msgType      | byte | n/a    | Message Type                   | §2.1
    3       | 1     | orig         | byte | n/a    | Market Center Originator ID    | §2.1, §3.1
    4       | 1     | subMarketId  | byte | n/a    | Sub-Market Center ID           | §2.1, §3.2
    5       | 8     | sipTime      | long | BE     | SIP Timestamp (ns since Epoch) | §2.1
    13      | 8     | timestamp1   | long | BE     | Participant Timestamp          | §2.1
    21      | 8     | partToken    | long | BE     | Participant Token (internal)   | §2.1
    --------|-------|--------------|------|--------|--------------------------------|--------
    Total: 29 bytes

    Notes: [§2.1]
    - All outbound messages begin with this header
    - version field allows message format versioning during transitions
    - orig='D' indicates FINRA; subMarketId then identifies specific TRF
    - partToken is for UTP SIP internal use; recipients should ignore

--- VARIABLE LENGTH RULES ---

varbyte[] Fields [§1.2.1]
- Length is contained in the immediately preceding field in the same message
- Example: textLen (short) followed by text (varbyte[]) in AA message
- Read the length field first, then read that many bytes for the variable field

Odd Lot Attachments [§2.2.8]
- Number of attachments determined by olAttachmentCount field
- Size of each attachment determined by olAttachmentType:
  - Type '2': 6 bytes per attachment (Short Form)
  - Type '3': 12 bytes per attachment (Long Form)
  - Type '5': 16 bytes per attachment (ADF MPID Form)

Market Center Attachments [§2.4.2.1, §2.4.2.2, §2.4.3.1]
- Number of attachments determined by numMktCenterAttch field
- Size depends on specific message type

--- PARSING SEQUENCE ---

1. Read 3 bytes: version, msgCategory, msgType [§2.1]
2. Dispatch based on (msgCategory, msgType) tuple [§1.3]
3. Read remaining header fields (26 bytes for standard header) [§2.1]
4. Read message-specific fields based on message type
5. For Quote messages with appendages:
   a. Check nbboIndicator to determine NBBO appendage presence/type [§3.8]
   b. Check finraAdfMpidIndicator for ADF MPID appendage (long-form only) [§3.9]
   c. Check boloIndicator to determine BOLO appendage presence/type [§3.30]
   d. Check olAttachmentType and olAttachmentCount for Odd Lot attachments [§3.31]
   e. Parse appendages in order: NBBO → ADF MPID → BOLO → Odd Lot
6. For messages with Market Center Attachments:
   a. Read numMktCenterAttch
   b. Parse that many attachment structures

--- SPECIAL CASES ---

Short Form vs Long Form Selection [§2.2.1, §2.3.1]
Short form is used when ALL of the following are true:
- Symbol ≤ 5 characters
- Prices ≤ $655.35 (max value for 2-byte short with 2 decimals)
- Prices use only 2 decimal places
- Sizes < 65,535
- Quote: Not from FINRA
- Trade Short Form: Sale condition ≠ 'R' (Seller)

Timestamp Handling [§2.1, §2.2.2, §2.3]
- timestamp1: Always participant timestamp
- timestamp2: 
  - From Exchange: Set to 0
  - From FINRA ADF/TRF: Contains FINRA proprietary feed timestamp
  - If no proprietary feed: Set to 0

Trade ID Uniqueness [§2.3]
- tradeId is unique per: (orig, subMarketId, symbol, session)
- For As-Of trades (TQ): tradeId is pass-through, no uniqueness guarantee

Price Level Removal [§2.2.8]
- An Odd Lot Price Level with olPrice=0 and olSize=0 indicates removal

Message Retirement Schedule [§1, §2.2]
- QE, QF messages: Retiring April 27, 2026
- QM message: Continuing support
- New QA, QB, QC, QD messages: Available April 27, 2026

Round Lot Changes [§1, §2.4.1.4]
- Effective November 3, 2025: New Round Lot tier designations
- Quote sizes now in actual shares (rounded down to round lot multiple)

Fractional Share Support [§1, §2.3]
- New trade messages (TM, TN, TO, TP, TQ): Effective February 23, 2026
- Volume fields use 6 implied decimal places for fractional share support

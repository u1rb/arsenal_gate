# Result


````markdown

Okay, let's break down the plan to refactor `cxx_examples/read_stream.c` using the `PacketStream` abstraction inspired by `tests/c_refactor.c`.

**Core Goal:** Abstract the process of reading rows from a Parquet file (or potentially multiple merged files later) behind a unified `PacketStream` interface. The user should interact with the stream on a row-by-row basis using a `packet_stream_next()` function (or equivalent mechanism) and accessor functions, without needing to manage the underlying Arrow C Stream batches directly.

**Plan:**

1.  **Define the `PacketStream` Abstraction:**
    *   Introduce a `PacketStream` struct similar to `c_refactor.c`.
    *   Define a `PsKind` enum to identify the underlying implementation (e.g., `PS_PARQUET_SINGLE`, potentially `PS_PARQUET_MERGED` later).
    *   Use a `union` within `PacketStream` to hold a pointer to the specific implementation's state struct (e.g., `ParquetReader*`).
    *   Define function pointers or use a dispatch mechanism (like the `#define` in `c_refactor.c` or a switch statement) for common operations like `next` and `release`.

2.  **Define the Row/Packet Concept:**
    *   **Decision:** Instead of returning a distinct `Packet` struct per row, we will modify the stream's internal state to point to the current row. The `_next` function will return `true` if a row is available and `false` at the end of the stream.
    *   Accessor functions (e.g., `packet_stream_get_int32`) will operate on the `PacketStream` object to retrieve data for the *current* row based on the internal state. This avoids complexities with `Packet` lifetime management and copying row data.

3.  **Implement `ParquetReader` (Single File):**
    *   Create `struct ParquetReader` to manage the state for reading one Parquet file.
    *   **State:**
        *   `struct ArrowArrayStream arrow_stream`: The underlying stream obtained from `export_parquet_file_to_stream`.
        *   `struct ArrowSchema schema`: Cached schema from the stream.
        *   `struct ArrowArray current_batch`: The currently loaded Arrow record batch.
        *   `int64_t next_row_in_batch`: Index pointing to the next row to be consumed within `current_batch`.
        *   `bool stream_ended`: Flag to indicate if `arrow_stream.get_next` has signaled the end.
        *   `uint64_t total_rows_processed`: Counter for total rows yielded.
    *   **Initialization (`parquet_reader_init_stream`):**
        *   Accepts the file path.
        *   Allocates `ParquetReader`.
        *   Calls `export_parquet_file_to_stream` to populate `arrow_stream`.
        *   Calls `arrow_stream.get_schema` to populate `schema`.
        *   Calls `arrow_stream.get_next` to fetch the *first* batch into `current_batch`. Handles potential errors or empty initial stream.
        *   Initializes `next_row_in_batch = 0`, `stream_ended = false`, `total_rows_processed = 0`.
        *   Wraps the `ParquetReader` pointer in a `PacketStream` struct (setting the `kind` and `impl` fields).
        *   Returns the `PacketStream*`.
    *   **Next Row Logic (`parquet_reader_next`):**
        *   This function will be called by the main `packet_stream_next` dispatcher. It returns `bool`.
        *   **Check Batch End:** If `next_row_in_batch >= current_batch.length`:
            *   Release the `current_batch` (`current_batch.release(&current_batch)`).
            *   Call `arrow_stream.get_next` to fetch the next batch into `current_batch`.
            *   Handle errors from `get_next`.
            *   If `get_next` returns an empty batch (`current_batch.release == NULL`), set `stream_ended = true` and return `false`.
            *   Reset `next_row_in_batch = 0`.
        *   **Check Stream End:** If `stream_ended` is true, return `false`.
        *   **Advance:** Increment `next_row_in_batch`.
        *   Increment `total_rows_processed`.
        *   Return `true` (indicating a row is ready).
    *   **Cleanup (`parquet_reader_cleanup`):**
        *   Releases `schema` (`schema.release`).
        *   Releases `current_batch` if it's valid (`current_batch.release`).
        *   Releases `arrow_stream` (`arrow_stream.release`).
        *   Frees the `ParquetReader` struct itself.

4.  **Implement Data Accessor Functions:**
    *   Create functions like `packet_stream_get_int32(PacketStream *stream, int col_index)`, `packet_stream_get_string(...)`, etc.
    *   These functions will:
        *   Take the `PacketStream*` and the column index as input.
        *   Access the underlying `ParquetReader` state via `stream->impl.parquet_reader`.
        *   Use the `schema` to determine the data type of the requested column (`schema->children[col_index]`).
        *   Access the correct child array within the `current_batch` (`current_batch.children[col_index]`).
        *   Use the `next_row_in_batch - 1` (since `_next` increments it *after* making the row available) as the row index into the column array.
        *   Extract and return the data, handling validity buffers (nulls) appropriately.
        *   Perform necessary type checking and error handling.

5.  **Refactor `main` in `read_stream.c`:**
    *   Remove direct calls to `export_parquet_file_to_stream`, `get_schema`, `get_next`.
    *   Call `parquet_reader_init_stream` to get the `PacketStream*`.
    *   Use a loop: `while (packet_stream_next(stream))`
    *   Inside the loop, use the new accessor functions (`packet_stream_get_int32`, etc.) to get data for the current row.
    *   Print or process the row data.
    *   Call `packet_stream_release(stream)` after the loop.

6.  **(Future) Merging Multiple Streams:**
    *   A `ParquetMerger` implementation could be added later.
    *   It would manage multiple `ParquetReader` instances.
    *   Its `_next` function would need to peek at the next row (requiring accessors to get key columns) from each underlying reader and use a merge algorithm (heap, loser tree) to determine the overall next row. Data accessors would need to delegate to the winning underlying reader.

This plan provides a clear path to abstracting the Parquet reading logic behind a row-oriented interface, mirroring the structure of `c_refactor.c` while adapting to the specifics of reading Arrow C Stream data.
````
